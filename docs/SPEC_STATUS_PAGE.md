# Spec: Admin app / Status Page (`status_page/`)

## Role

The Admin app: a set of pages, most of them a browser dashboard for seeing what the stack is doing without a terminal tab per service: health, the live decision pipeline, mood over time, the history of the companion's looks, chat and logs. It is a **separate process** from the brain (`deskmate-status.service`, `python -m status_page.app`), deliberately: it must stay up and restartable when the brain hangs or crashes, it cannot slow the brain, and iterating on it never interrupts the companion.

## Principles

* **Read-only, except the named writing pages.** It never writes `state.db` (opened `?mode=ro`), never controls services (only queries `systemctl --user is-active/show`), and never executes anything the browser names. The pages that write are **Build** (see [ADR_BUILD_YOUR_LOOK.md](ADR_BUILD_YOUR_LOOK.md)), whose routes, under `/api/build/`, only ask the brain to preview or build a look, and **Model settings** ([ADR_MODEL_SETTINGS_PAGE.md](ADR_MODEL_SETTINGS_PAGE.md)), whose routes, under `/api/model-settings/`, only relay a model's settings, hold, credit and face landmarks to the brain, which validates and writes them; in both the brain validates what they pass on. Every route that is not a `GET` lives under a writing page's prefix (`WRITE_PREFIXES`), a middleware refuses any other non-`GET`/`HEAD` request with `405`, and a writing route also needs the page's own `Origin`, the header `X-Deskmate-Admin: 1` and a small JSON body. A new writing page needs its own decision and an entry in `WRITE_PREFIXES` (the Models page of [ADR_MODEL_IMPORT_PAGE.md](ADR_MODEL_IMPORT_PAGE.md) is proposed).
* **Local only.** Binds `[status] host:port` (default `127.0.0.1:8780`); a middleware rejects any request whose `Host` header is not that address (DNS-rebinding guard). The page shows chat history and prompts, so do not bind it beyond loopback.
* **Degrades visibly.** A brain that cannot be reached is a banner and a red dot, not an empty page; the rest (units, endpoint probes, database, logs) keeps working.
* **Config:** the daemon's own `config.toml` (`get_settings()`), plus `[status]`: `host`, `port`, `units` (journalctl `--user` units shown as log panes), `extra_logs` (name $\to$ file path).

## Endpoints

| Route | Purpose |
| --- | --- |
| `GET /` | `static/index.html`: markup only. |
| `GET /static/...` | The UI's CSS and ES modules (`StaticFiles`, mounted last so it never shadows an `/api` route; covered by the same Host-header guard). No build step, no external assets (the Build page's 3D viewer is three.js, vendored under `static/vendor/three/` with its licence and a note of where it came from; `index.html` maps `three` to it with an import map). |
| `GET /api/overview` | One poll (the page polls every 3 s): unit states, backup status (`[storage] backup_dir`'s `state.db` mtime plus `deskmate-backup.timer`), brain `GET /health` + `GET /api/status` + `GET /api/skills`, endpoint probes, and from `state.db` the last 40 chat turns (each assistant turn joined to its `reply_raw` row, when it has one; a database from before that table still reads), 12 memory notes, `agent_state`, traits and mood. |
| `GET /api/events` | Relays the brain's SSE event stream (`GET /api/events`, see [SPEC_BRAIN.md](SPEC_BRAIN.md) "Event Stream") so the browser talks only to this service. `?since=` / `Last-Event-ID` pass through; if the brain is unreachable it emits a `brain-down` event and ends, and the browser's `EventSource` retries. |
| `GET /api/history?kind=mood\|traits&hours=` | Time series from `personality_history`, step-function points per name, down-sampled to $\le 600$ per series, anchored by the last point before the window (1 hour to 30 days). |
| `GET /api/looks` | Every version in `manifest.json`, newest first: `version`, `created_at`, `status`, `summary` (template, outfit, footwear, worn accessories), `palette`, `has_picture` (a PNG exists in `<deploy_dir>/looks/`) and `kept` (its `.glb` is still in `assets/`), plus `current` and `locked` (the current look is an imported model the companion is keeping, derived from the manifest and `agent_state.look_unlocked_for`, read-only; see [ADR_IMPORTED_LOOK_LOCK.md](ADR_IMPORTED_LOOK_LOCK.md)). Read straight from the manifest file; a missing or unreadable manifest gives an empty list. |
| `GET /api/animations` | Which animations each installed body gets from each installed animation library (`brain.appearance.models.animation_matrix`, read-only, computed from the files under the deploy directory): `libraries` (`name`, `clips`, `joints`) and `bodies` (`body`, `installed`, `held`, `credit` (who made it and under what licence, for a model that came with that recorded: a Sketchfab one), and per library `fits`, `roles`, `sit` (`chair` / `ground` / null) and `gaps`, the bones of the library the body lacks, whose tracks are dropped). `libraries` is null for a body whose rig was never inspected and `{}` for one with no rig of the libraries'. An unreadable deploy directory gives empty lists. |
| `GET /api/looks/{version}.png` | The version's picture (`<deploy_dir>/looks/look-v{N}.png`, rendered by the brain, see [ADR_LOOK_HISTORY.md](ADR_LOOK_HISTORY.md)); `404` if not rendered yet. The version is an integer in the route, never a path. |
| `GET /api/build/options` | What each body can use, from the brain's `GET /appearance/options` (read-only): per body, which controls apply and their choices, with the reason when one does not. A brain that cannot be reached gives `502`. |
| `GET /api/build/spec?version=` | The stored spec of a version (the current one by default), from the manifest, for the Build page's "start from". `404` when there is none. |
| `GET /api/build/animations?body=` | The clips the viewer can play for a body: the libraries that fit its rig, each clip with the roles it fills and the speed it is played at, and the bones the body lacks (`brain.appearance.viewer_files.body_animations`). |
| `GET /api/build/model/body?body=`, `/outfit?body=&outfit=`, `/library?body=&library=`, `/accessory?socket=&item=` | The `.glb` of an installed, usable (not held) body, an outfit model made for it, an animation library that fits its rig, or an accessory that is a model file (looked up by the socket and item `discover_accessory_models` lists), for the viewer. Named by id and looked up in the catalogs; never a path. `404` for anything else. |
| `POST /api/build/preview` | **Writes (Build).** Asks the brain for a throwaway build and picture of a spec (`POST /appearance/preview`); nothing is published. The brain's answer, including its refusal of a spec (`422`) or a second preview at once (`409`), is passed on. |
| `GET /api/build/preview/{id}`, `/picture`; `DELETE /api/build/preview/{id}` | The preview's state and picture (`id` is a 32-digit hex token, never a path); `DELETE` discards it. |
| `GET /api/model-settings/models`, `GET /api/model-settings/get?body=` | The installed bodies (held ones marked, customised ones flagged), and one body's settings with what can be chosen for it, relayed from the brain (`GET /appearance/model-settings/models`, `GET /appearance/model-settings`). |
| `POST /api/model-settings/validate`, `PUT /api/model-settings/save`, `DELETE /api/model-settings/stale?body=` | **Writes (Model settings).** Check, save (atomically, beside the model) and clean up a body's `<model>.config.json`. The brain's refusal (`422`, with each reason) is passed on. A save applies from the next build; it rebuilds nothing. |
| `PUT /api/model-settings/hold`, `/credits`, `/face` | **Writes (Model settings).** Hold or release a custom model, edit its credit and licence record, and its face landmarks: each is its own file, saved on its own. |
| `POST /api/model-settings/alignment`, `POST /api/model-settings/rebuild` | **Writes (Model settings).** A throwaway build with one item in every socket using settings that are not saved (read with the Build page's `/api/build/preview/{id}` routes), and a rebuild of the current look (the same call Apply makes) when it is on the model. A body of up to 64 KB is accepted here (a settings file), 16 KB elsewhere. |
| `POST /api/build/apply` | **Writes (Build).** Makes a spec the companion's next look (`POST /appearance/generate`): a normal new version. How the build ends arrives on the event stream (`appearance.done` / `failed`). |
| `GET /api/logs/{source}` | SSE tail of one configured source: `journalctl --user -u <unit>.service -o short-iso -n 200 -f`, or `tail -F -n 200 <file>`. The client names a source; it can never supply a command or path (unknown $\to$ 404). |

Endpoint probes (`/models` of the local and classifier LLMs; each `[voice.tts.remote.*]` instance's capabilities endpoint) use a 2 s timeout; disabled instances show as such rather than failing.

## Sizing

Every length is in `rem` and lives in `css/`, so the page scales with the viewer's root font size and browser zoom. The JavaScript carries **no size values**: swatch shapes are CSS classes (`.sw`, `.sw.dot`, `.sw.box`), and the chart tooltip is placed by CSS (`.tip`) from two custom properties, `--tip-x`/`--tip-y`, that the script sets to the measured cursor position (a coordinate, not a design size, so it is the one place a pixel value appears); the gap from the cursor and the side it sits on (`.flip-x`/`.flip-y`, toggled when a measurement shows it would leave the chart) are CSS. Two tests enforce this: no `px` length in `css/`, and no size-bearing inline style in `js/`. The chart's SVG user units (its `viewBox`) are unitless geometry, not CSS sizes.

JavaScript and CSS are formatted with Prettier's defaults, written out in `.prettierrc.json` (80 columns, two spaces, double quotes, semicolons, trailing commas, and the HTML inside `html` templates left as written); `status_page/static/vendor/` is excluded by `.prettierignore`, because third-party code is kept byte for byte as released (a formatter that rewrote its quotes made the vendored three.js differ from the npm package it was checked against). Check with `npx prettier --check status_page/static`. New and split modules start with `// @ts-check` and describe their data in JSDoc (`types.js` holds the shapes the brain sends); `npm run check` in `status_page/` runs the strict type checker (`tsc --noEmit`, dev-only tools in `package.json`, nothing is built) and a test in the suite runs it too when the tools are installed. See [ADR_ADMIN_UI_ARCHITECTURE.md](ADR_ADMIN_UI_ARCHITECTURE.md).

Each panel module exports one `initX()` and reacts to bus events; adding a panel means a new module, a new `initX()` call in `main.js`, and (for a tab) an entry in `tabs.js` and `index.html`.

## UI

Nine tabs (location hash), a live-connection indicator, a light/dark toggle (`prefers-color-scheme` plus an explicit override; chart colors are the validated categorical slots 1-3 for both modes), and a problems banner (a unit not active, brain/LLM/TTS unreachable, overlay not connected, database error).

* **Overview:** services, endpoints, companion (name, voice, presence, look, overlay connection, uptime), **backup** (target, age of the last good snapshot, timer state, and a live line `Next backup scheduled: <local time> (in 8 hours, 20 minutes)` from the timer's next trigger, which counts down in the browser, switches to minutes and seconds inside the last hour, and turns bold in the last 5 minutes; a problem is raised if no `backup_dir` is configured, no backup has been made, the last is over 36 h old, or the timer is not active), "feeling now", live mood and trait bars with the last change, placement (the picture of the current look, avatar, active window, screens).
* **Thinking:** a feed of cards, one per user turn (events grouped by their `turn` id): the prompt (collapsed), routing decision and reason, the pool chosen (including "wanted cloud, none configured, fell back"), each model call with latency and tokens, the model's reasoning when `[llm.local] reasoning = true`, reply format (flagging an unstructured reply), skills run (`Did:`) or refused (`Refused:`), the **raw response** (the model's reply exactly as returned, from the `reply.raw` event, with a word diff against the text that was finally said and saved), the spoken reply, and per-sentence voice timing. Reflection results appear as their own cards; a "Background events" toggle adds placement moves and mood shifts. A note states whether reasoning is on, since it is off by default.
* **Skills:** every registered skill (enabled or not) with its description, arguments (enum values shown), state, and in-memory usage counters (calls, failures, refusals, last used, last error; reset on brain restart), a live list of skills run or refused since the page opened, and the exact skills block appended to the model's system prompt (the only way the companion knows what it can do). An **Installed Agent Skills** table lists third-party `SKILL.md` skills: display name and canonical `source/name` id, purpose, trust tier, enabled / pinned / exposure (`absent`, `discoverable`, `stub`) with the stub's token cost, source, commit and category, license, notes (scripts, dangerous tools, scan findings), and whether it runs (not yet: the agent runtime does not exist, and no skill is put in the prompt). The heading carries the budget meter (enabled and pinned counts, stub tokens against the budget, the context size it was derived from). Rejected directories follow, with the reason. The table is **read-only**, like the rest of the page; changes are made with `python -m brain.skills.manage` or the brain's `POST /api/skills/state`. Data comes from the brain's `GET /api/skills`, fetched with each overview poll.
* **Mood timeline:** valence/energy/stress (or up to three chosen traits) as step lines over a selectable range, hover crosshair with values, a table view, and a strip of derived *feelings* along the bottom. The feeling is computed in the page from the three mood values (stress $\ge 65$ nervous/anxious; valence $\ge 65$ excited/happy; $\le 35$ sad/frustrated; then sleepy/energetic by energy; else content/down/neutral); it is never stored. Live `personality.*` events extend the chart without a reload.
* **Animations:** every installed library (its clip count, the clip names in a collapsible), then every body with what each library gives it: the roles it plays, whether it sits on a chair or the ground, and how many bones it lacks (their tracks are dropped). Read-only; libraries are installed with `add-animations`. Loaded when the tab is shown.
* **Looks:** every version of the companion's appearance, newest first, as a grid of cards: the picture, `Version N`, a *current* badge, a one-line summary, the build date, and "rebuilt on request" where the `.glb` is no longer kept (the pictures are kept for every version; see [ADR_LOOK_HISTORY.md](ADR_LOOK_HISTORY.md)). A version whose picture is not rendered yet shows "picture pending…". When the look is locked a note says so and how to free it. **Read-only, like the rest of the page:** there is no restore control. To go back to a look, tell the companion its number ("go back to version 12"); the tab is the reference for choosing one. Loaded when the tab is shown.
* **Navigation:** a sidebar, not a row of tabs, so the app can grow: pages are grouped under a name, **Overview** (Overview, Logs), **Companion** (Thinking, Mood timeline, Chat & memory, Skills), **Appearance** (Looks, Build, Animations) and **Models** (Model settings; the Models import page of ADR_MODEL_IMPORT_PAGE joins it). A page is still a panel chosen by the location hash, so it is linkable; a new page is a button in one group plus its panel (a test fails if a panel is not in the menu). On a narrow screen the groups run across the top.
* **Model settings** ([ADR_MODEL_SETTINGS_PAGE.md](ADR_MODEL_SETTINGS_PAGE.md); the second page that writes): the installed models in a list (held and customised ones marked) and, for the chosen one, four sections edited as a draft that is held until **Save**: *Animations and roles* (libraries switched on or off, animations switched off, and per role Automatic / these clips, the first its own and the rest alternatives / Off, each clip playable in the viewer; a body no library fits says so and has no roles to edit), *Accessories* (which sockets and items, and per item a placement for this model: offset, scale, rotation, drawn live in the viewer when the item is a model file, judged on the alignment sheet when it is parametric), *Pose and face* (`face_yaw`, `emissive_gain`, `relax_arms`, `arm_spread`, bones to turn, and the face landmarks, saved on their own) and *Availability and credits* (hold or release a custom model with a reason, the credit and licence with what the licence asks). The brain validates the draft as it changes (a refused one cannot be saved, and the reasons are listed); entries naming something no longer installed are listed as "no longer available" with a button to remove them. After a save the page offers **Rebuild the current look** when the look is on that model. The **alignment sheet** builds the model with one item in every socket from the unsaved draft, about 20 s, and never publishes. The viewer is Build's; it does not show a held model. Dragging an accessory in the viewer is not done: placement is by numbers. Code: `settings.js` (starts it and handles edits), `settings-doc.js` (the edits, pure), `settings-view.js` (the forms), `settings-stage.js` (the viewer), `settings-state.js`, `settings-ui.js`.
* **Build** (a page that writes; [ADR_BUILD_YOUR_LOOK.md](ADR_BUILD_YOUR_LOOK.md)): a form built from what the chosen body can use (`GET /api/build/options`): body, outfit, footwear, the four colors and the surface, the four proportions and the accessories, each beside the part of a drawn figure it goes on (a socket the body cannot carry is left off and named). A control the body cannot use is shown switched off with the reason; a color is enabled only while the outfit, footwear or accessories chosen use it (`colors` in the options), and an installed model's surface and `primary` are always off. **Start from** is a choice the user makes: nothing is loaded when the page opens, and the choices are a look you have had (the current one or any version) or a new look on a body, in a picker with two collapsible groups (a closed group stays closed, remembered in the browser) and a filter that matches every word typed against what a look is made of (body, outfit, accessories); Enter takes the first match. A page that finds the brain's options older than itself (no `colors`) still works, treating every color as used, and a failure while loading is shown on the page. A loading banner is up while anything loads. A live 3D viewer (three.js, `static/js/viewer.js`) shows the installed body, its outfit model and any clip the body supports, played the way the build wears it (bones the body lacks are dropped, the hips' travel is scaled by the ratio of the two rests' hip heights, a slowed role is played slower); a body's outfit model is shown with the body stripped to its head and neck, as the build does, so skin does not show through the cloth; the animations are a list to the right of the model, as tall as the model, each with the role(s) it fills (`role: idle`, `roles: talk, greet`; a role's variants count as the role) and an animation no role uses shown disabled, with a play/pause button the same width under it; a built-in body has no model to show and says so. Accessories that are model files (hair, a beard) are drawn on the body too, fixed to their socket's bone so they move with the clip, on a rig with Quaternius-style `head` and `neck_01` bones and for the head-top and neck sockets; under any accessory chosen that the viewer does not draw (a parametric item, another socket, a rotated placement) a *Viewable in Preview only* note appears. The viewer is a guide to shape and motion, not the overlay (a different renderer): the rest of the accessories, the colors and the proportions appear only in **Preview**, a throwaway build of the whole look (about 20 s; one at a time; the previous picture stays, marked out of date, until the new one arrives). **Apply** is enabled only when the form differs from what was loaded (a new look on a body always can be) and makes the spec the next version; the page says before it whether that ends the imported-look lock. Work in progress (a preview building, a build) is shown with a spinner and a pulsing bar. Loaded when the tab is shown.
* **Chat & memory, Logs:** recent turns with provider/escalation, each assistant turn that has a recorded raw reply carrying a collapsible "raw response" with the same comparison (the diff is between the dialogue the model produced — the `say` of a structured reply, else the whole text — and the saved text, so it isolates what the cleanup removed or added; open comparisons stay open across the 3 s re-render), memory notes; log panes per source with filter, pause and clear (a dropped log stream is re-opened rather than auto-resumed, to avoid replaying the backlog as duplicates).

## Deployment

`deploy/systemd/deskmate-status.service` (placeholders `@REPO_ROOT@`, `@VENV_PYTHON@`, as the brain's unit); installed by `deploy/install.sh`, enabled with `systemctl --user enable --now deskmate-status.service`. It is `WantedBy=default.target` and deliberately not tied to the brain or the graphical session. It stops at once: the event and log streams never end on their own and uvicorn waits for every open connection, so they watch a stop flag (`_stopping`, set when the server is told to shut down) and finish, with a 5 s backstop that closes anything left and `TimeoutStopSec=15` in the unit. Without that a restart waited for systemd's timeout and was killed.

## Tests

`brain/tests/test_status_page.py`: Host-header guard (including on `/static`), log-source whitelisting, read-only database access, missing-database handling, every asset the index references is served, every JS `import` resolves, the static mount cannot serve files outside its directory, `/api/animations` (libraries and per-body fit, empty without a deploy directory), and `/api/looks` (newest first, picture flag, summary, missing manifest, picture 200/404). The Build page: no write outside `WRITE_PREFIXES` (every non-`GET` route is under one, and any other write is `405`), the Origin, header and body checks, the brain's refusals passed on, an unreachable brain as `502`, preview ids that are never paths, the viewer's routes refusing paths and held bodies, start-from, the import map's targets being served, and the form logic (run with node, skipped without it). `brain/tests/test_build_options.py`, `test_viewer_files.py` and `test_preview.py` cover the brain side.
